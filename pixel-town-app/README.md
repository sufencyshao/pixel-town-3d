# 像素小镇 · 白板实验室 v0.8.1

基于原 AI Chat 模型接入内核制作的独立 Electron 应用，当前提供俯视 2D 白板中的居民生活、键盘操控和相遇对话。目标是逐步发展成高自由度生活游戏；当前没有完整地图、建筑、农场、经济与任务系统。

项目独立放在 `pixel-town-app/`，复制复用原 `main/llm.js`，拥有自己的主进程、界面、素材副本与存档。原 AI Chat 源码和数据不由本应用覆盖。

## 启动

在本项目目录运行：

```sh
npm start
```

启动脚本优先使用本项目依赖，也可复用上级现有 Electron。把项目单独搬走后，先安装依赖：

```sh
npm install
npm start
```

`npm run build:mac` 的目标为 `dist-mac/像素小镇.app`。生成后可直接打开，也可复制到“应用程序”。脚本采用本机临时签名，不包含正式分发签名与公证。

## 游戏操作

主界面是白板游戏场景，顶部为时间与人数，底部为暂停、速度、手记与幕布工具。没有常驻聊天栏或人物参数侧栏。右上“设置”集中管理居民、人物档案和 API；打开设置暂停生活，返回恢复此前的运行状态。

- 点击居民显示临时互动条；点击空白地面让选中人物走过去，拖动人物直接调整位置。
- 点击“操控 TA”，用 WASD 或方向键移动；“放手让 TA 生活”恢复自主活动。取消选择也会释放控制。
- “找邻居聊聊”选择另一位居民，两人先走向相遇区，到达后分别回复；“问问近况”打开临时聊天窗口。
- “打招呼”“坐一会儿”触发活动。点击人物 → “更多动作”，可选择点头、摇头拒绝、交谈手势、欢呼、跳跃、游玩、惊讶、职业工作、偷懒、打盹和躺下；菜单中的动作在原地播放。可暂停、选择 1× / 2× / 4× 速度，或推进时间。
- 点头播放一次；摇头左右各约 30°，720 ms 内快速摇两下，回正停留 480 ms 后恢复待机。重复点击从首帧重播。交谈手势循环播放；绑定 API 的人物在对话中使用模型选择的动作。
- 每天 06:00 日出、12:00 太阳升到高处、18:00 日落，随后月亮升起；天空、地面、星光与人物光照随游戏时钟平滑变化。暂停、1× / 2× / 4× 和推进五分钟同步作用于昼夜。
- 点击顶部时间，可等到下一次日出、正午、日落或夜晚。推进只前进不倒退，已经过去的时刻会进入下一天；正在等待的旧时刻模型回复会取消。当前游戏时段也提供给人物和动物 API。
- “手记”查看生活、心声、对话、关系与错误；“幕布”展开点阵、行为标记与缩放工具。关闭点阵和行为标记，可保留干净场景。

默认六位居民。在设置 → 居民与人物 → 管理人数与居民中，可勾选成员或调整为 1–60 人。形象数量由 assets/roster.json 决定，本轮扩展为 40 套常规人物及 5 位原 Codex Mini 访客；超过目录人数复用形象，但姓名、人设、模型绑定、记忆和关系各自独立。离镇停用人物，保留档案。

## 我的主角与捏脸

右上「创建主角」，或设置 → 我的主角 → 创建我的主角，打开形象窗口。窗口顶部可切换「游戏预设形象」和「自由捏脸」，两种方案都保留，支持随机、恢复保存造型、全身 / 五官放大、四方向和动作实时预览。

「游戏预设形象」提供 8 套完整造型，直接复用小镇居民的原始人物与连续动作图集，比例、画风和笔触相同。可调整发色、服装配色、肤色和瞳色，添加方框眼镜、圆框眼镜、蝴蝶结或围巾；「原色」恢复素材本身的配色。发型、服装版型与原有鞋帽随完整预设切换，当前不单独拆换这些部分。

「自由捏脸」保留 v0.2.1 原生 128×160 图层与 8 套衣橱，以及原来的 30 个参数：性别、肤色、脸型、9 种发型、刘海、发色、眉形眉色、眼型瞳色、鼻型、嘴型、6 种表情、腮红、雀斑、身高、体型、肩宽、胸部轮廓、上装下装及配色、鞋型鞋色、帽子帽色、配饰与配色。身体参数改变像素轮廓，颜色支持色板和自选；尚不支持手绘或上传外观。

新建主角默认使用游戏预设；此前保存的自由捏脸主角继续使用原方案。切换时保留两套专属造型参数，保存后重启也能恢复；预设方案的换色不会覆盖原捏脸的发色、肤色与衣服颜色。游戏预设主角的“动作与表情”支持新的点头、摇头拒绝与交谈手势；自由捏脸沿用自己的可用动作。

保存并进入小镇后，主角由玩家控制，WASD / 方向键移动，也可点击地面行走、拖动摆放。点击主角的「动作与表情」可选择站立、挥手、欢呼、跳跃、坐下、游玩、惊讶，偷懒、打盹、躺下，以及平静、开心、害羞、认真、惊讶、难过表情。动作原地播放并保持操控，按键可随时恢复行走。主角也可主动邀请居民相遇交谈。

主角独立于 1–60 位 NPC 人数设置，不自行触发模型决策或随机生活。外观、名字、位置、记忆和关系保存在本应用的独立存档中；重新捏脸会保留现有生活记录。关闭捏脸不保存草稿；保存失败可继续编辑；保存期间暂时锁定编辑，避免重复提交。重启后可点击主角「操控主角」，或设置 → 我的主角 → 用这个主角进入小镇。

## 人物与 API

设置 → 居民与人物 → 点击居民，可编辑姓名、职业、形象、性格、背景、兴趣、说话风格和 Markdown 档案。每人分别选择服务商、模型、Temperature 与最大输出 Tokens。可从目录中的常规人物与 Codex Mini 形象中选择，并通过「可选人设预设」填入背景与性格，尚无图片上传或角色绘制器。

设置 → API 与生活调度中添加服务商，支持 OpenAI 兼容协议与 Anthropic，以及模型列表与连通性测试。每人可绑定不同服务商；需要每人不同密钥时，为每人创建独立服务商记录。接入内核复用原 AI Chat 模块，包含 macOS 系统代理检测。服务商保存成功表示主进程已完成落盘。

### 让 API 表达人物的想法与动作

点击已绑定 API 的人物 →「让 TA 想一想」，模型根据独立人设、记忆、需求和邻居状态，选择下一步动作并返回心声与必要的台词。「问问近况」与人物之间的对话也在同一次回复中选择动作，例如赞同时点头、拒绝时摇头，或继续自然交谈。

心声与说出口的话分开：沉默时显示心声气泡；有台词时使用对话气泡，选中人物的互动条另显示心声。聊天记录保存本次动作和心声，手记可以单独筛选心声。模型只能选择当前形象实际具备的动作，不会替缺少素材的 Mini 播放摇头。

设置 → API 与生活调度 → 开启「模型自主生活」，已绑定的人物会持续自行决定下一步，无需点击触发。模型参考自己的生活方向、持续目标、职业日常、精力、社交需求、游戏时段和近期真实经历，选择工作、散步运动、休息、游玩或邀请邻居；这些人物的行为由模型延续，不会被本地随机动作覆盖。长行为遇到精力过低、社交需要或天色变化时，也可重新考虑安排。模型可以决定实际目的地与行为时长；移动到达后才计算在目的地的活动时间。

主动邀请在相遇后复用邀请者已生成的开场白。对方的模型决定如何回应，两人可继续追问、表达不同意见、拒绝或结束交流。一段对话不设固定轮数上限，每个人分别给出自己的感受与是否继续，双方的好感变化可以不同；任何一人不愿继续时结束这一段，之后再各自生活。没有绑定 API 的对话方使用本地回应。

手动动作、接管、拖动摆放、变更人物配置或离镇会使旧回复失效；手动接管取消网络等待并立即允许键盘移动。关闭模型自主生活会取消正在等待的自动请求。API 失败或输出无效时，人物先原地等待并记录错误，不编造模型的想法。未绑定 API 的居民继续使用本地规则；主角仍由玩家控制。

「从原 AI Chat 复制配置」现在先列出候选服务商，可只勾选需要的配置。复制后在小镇加密保存，原应用只读访问。

### 基础资料、个人目标与每日日志

设置 →「基础资料与日志」可编辑小镇名称、共同背景、生活氛围与公告。45 位目录人物分别有按职业和兴趣初始化的生活方向与日常参考；可以逐人修改，或清空当前目标，让下一次模型自行拟定。职业日程提供参考，模型可以根据当前需求改变安排。档案中的未选人设预设不会混入当前身份。

模型每次收到实际功能与可用动作说明、坐标与公共区域、当前时刻和需求、自己的持续目标与近期目标、附近居民的公开状态，以及自己的近期日志。没有建筑、物品库存或职业产出的功能会明确说明，避免模型把计划说成已经完成。点击人物的「生活方向」→「查看 TA 收到的资料」可查看当前基础上下文，这个查看操作不调用 API。

场景右上「每日日志」、人物互动条或基础资料设置均可打开日志。人物、动物、玩家主角、小镇、公共区域、太阳和月亮都有独立记录；未入住成员也保留档案，入住后继续记录。日志按游戏日期保存，支持类别筛选、翻页与导出整天 Markdown。动作开始、到达、结束、目标计划、私人心声、说话、听到的回应和近处见闻分别标记；动物记录感官刺激与自然行为。远处事件与他人的私人心声不作为个人见闻。

完整日志存入独立 `journals/` 目录，不受场景手记最近 180 条的限制。每次模型调用只携带自己最近三个有记录的游戏日中最多 12 条近期记录；完整历史仍可查看和导出，目前没有语义检索。日志记录、查看、导出和资料编辑本身不增加 API 调用。此前仍保存在场景手记中的事件会迁入相应参与者和小镇日志，未保存的旧历史无法补回。

### 疲劳、休息与个人心情

人物疲惫时可选择「打盹」或「躺下」，连续工作感到压力时也可能「偷懒」。这三种行为是不同的选择：偷懒短暂放下事情，打盹小睡一会儿，躺下作较长休息；精力恢复速度和默认时长各自不同。自动选择无需玩家点击，已绑定人物由 API 根据自己的精力、时段、心情和目标作决定；本地规则人物按个人需求和性格选择。等待下一次 API 调度时不会持续扣精力，安静待着的心情可缓慢回稳；实际工作和活动仍有消耗。自动休息会在附近安排空位，避免多人和姓名叠在区域中心；手动摆放仍保留指定位置。去往休息区域时，到达后才开始恢复；睡着的居民不会被自动邀约打断，玩家仍可主动唤醒或操控。

点击人物 →「心情」查看心情、压力、精力、最近原因和感受，并进入每日日志。心情和精力分别变化：认真工作可以带来投入感，也可能累积压力；休息、爱好与活动身体可以恢复，听到关心或伤人的话、见到身边人的实际行为也会影响感受。普通意见分歧不会一律视作侮辱。他人的私人心声不会传播成个人见闻。

每个人依照保存的性格、兴趣和熟悉程度有不同倾向：低落时安静独处，或向已有关系的熟人倾诉；愉快时分享，也可以专注自己的爱好、继续做事或运动。模型会收到自己的情绪原因、近期变化和倾向，仍可根据具体处境改变主意。API 可以在原本同一次动作回复中给出个人心情变化和原因，不增加专门的心情评价调用；变化写入该人物的「心情」日志，并保存至下次启动。

偷懒使用坐姿/等候，打盹使用原姿势和像素 Z 标记。躺下使用 40 位人物与 5 位伙伴各自重新绘制的侧躺素材，包含弯膝、双臂、撑头、闭眼及连贯颈肩；手持工具收起，头部靠在小枕头上。预设主角使用对应素材并保留换色/配饰，自由捏脸主角以原外观图层绘制新的弯腿和手臂结构。运行帧为 256×256 真实透明硬边像素，4 帧循环显示睡眠提示；没有实体睡床或入睡起身过渡。伙伴也可通过“更多动作”选择躺下。按键可恢复行走，暂停与倍率同步影响播放。

全部角色的对照与逐帧复核见 [侧躺预览](build/validation/side-lying-v0.8.1/preview.html)，本次验证与安装记录见 [完成报告](build/validation/side-lying-v0.8.1/completion.md)。角色自然度的最终用户签收单独记录。

官方 DeepSeek Flash/Pro 的结构化生活请求使用非思考模式与 JSON 输出，避免小输出预算被默认推理占用；保留每个人保存的最大 Tokens、模型和 Temperature。其他服务商沿用兼容参数。参数依据 [DeepSeek 官方 API 文档](https://api-docs.deepseek.com/api/create-chat-completion/)。

### 批量分配 API

设置 → 居民与人物 / 动物与宠物 →「批量分配 API」，或 API 与生活调度 →「批量分配给人物」。每条服务商配置也提供「分配给人物」快捷入口。

先把每个 Key 保存为一条 API 服务商配置（同一服务商的不同 Key 可分别命名），再勾选人物与一个或几个配置。支持搜索、全选当前列表、只选已入住；未入住人物与动物也能提前配置，玩家主角不参与。

- 选择一个配置：把同一个 API 与模型一次绑定给全部所选人物。
- 选择多个配置：按列表顺序轮流均分（A / B / A / B），或连续按组均分（A / A / B / B）。分配是固定绑定，后续调用各自保存的配置；不在每次请求时随机换 Key。
- 每个配置可选择或输入模型名称。默认保留各人物原有 Temperature / Tokens；取消勾选后按每个配置指定的参数统一设置。
- 应用前显示每个人的新绑定与各配置分配人数，点击「应用到 N 位」一次保存。失败保留草稿且不部分应用；取消不修改绑定。主角、外观、人设、记忆与关系不受分配影响。

分配操作不访问模型 API，不把 Key 复制到人物档案中；成功即已写入独立存档，重启后仍保留。当前有模型任务进行时需等任务结束再应用。

本地规则人物不访问网络。模型自治关闭时，居民按需求、时间和性格规则活动，自动交谈使用本地模板。手动相遇交流、问近况、人物编辑折叠项中的模型决策测试，会按人物已保存配置调用模型。测试使用已保存的配置，未保存的表单修改不会生效。

“从原 AI Chat 复制配置”只有点击后才读取原正式数据中的服务商；人物编辑中也可复制原人设。导入为只读复制，不写回原文件，不复制原私聊。只有原开发数据目录有配置时，入口不会自动改读开发目录。

## 自动调用与费用保护

新存档默认关闭模型自主生活；明确开启后会保存该选择，重新打开应用仍继续自主生活。旧版存档不会因升级自动开启，正式安装时可按用户要求启用。暂停、打开设置或关闭自治会停止自动调用；正在手动操控的人物不参与自动决策。应用退出或电脑休眠期间不补演经历。

- 全镇自动任务最短间隔默认 60 秒，可设置为 15–3600 秒；手动操作不受该间隔限制。
- 每日生活逻辑调用上限默认 100，可设为 1–10000。自动、手动与失败请求均计入，以电脑本地自然日计算，区别于游戏内天数。
- 全镇同时执行一个生活模型 / 对话任务，按人物上次决策时间轮流安排。交流不设固定轮数上限，开始前检查初次双方所需额度；每次继续都检查剩余额度并计入调用次数。额度用完就停止追加回复，网络失败仍可能中断在第一句。
- 模型列表与连通性测试不计入生活上限；测试仍会访问服务商，可能产生费用。
- 逻辑调用次数不是 HTTP 尝试次数、Token 或金额预算。参数回退、503 重试可能产生多个 HTTP 尝试，界面的 Token 汇总也依赖服务商返回的 usage。

失败写入手记；人物模型决策失败先原地等待下一次决策。动物仍保留原有的自然行为回退。

## 存档与密钥

macOS 正式数据：`~/Library/Application Support/pixel-town-life/`；开发数据：`~/Library/Application Support/pixel-town-life-dev/`。可用 `PIXEL_TOWN_DATA_DIR=/绝对路径` 指定隔离目录。

密钥由主进程持有，实时快照不向界面返回密钥。通过 Electron `safeStorage` 加密落盘；系统加密不可用时拒绝保存密钥，不降级明文保存。加密数据依赖当前系统环境，复制到其他电脑不保证能解密。

本地游玩和没有密钥的存档不提前查询系统钥匙串。实际读取或保存 API 密钥时，macOS 可能请求钥匙串授权（尤其在应用更新后）；需要由用户在系统提示中处理。

写入临时文件后替换 `town.json`，保留上一份 `.bak`。主存档损坏时尝试备份恢复，并保留损坏副本。这是单份滚动备份，不能替代多版本备份；两份均损坏或无法解密时可能无法恢复。导出 JSON 不含密钥，目前没有界面导入存档功能。

## 当前边界

人物与动物的连续动画从每个目录的 animation.json 读取。游戏使用 PNG 横向图集的逐帧播放，遵循逐帧时长与单次 / 循环规则；随暂停冻结、随 1× / 2× / 4× 速度调节，不依赖 GIF 或逐帧文件加载。40 位人物各 14 组动作，自然动物 310 组，Codexmini 50 组，全库共 920 组。01～20 号的 frame_11/12 是已签收的背面走路两步，欢呼继续读取独立 cheer 图集；预设主角背面不叠加眼镜或面部表情。

运行资源复用 `../pixel_town_assets/tools/sync_roster.py` 同步，保留 PNG 原字节、256×256 帧与透明像素。40 人摇头采用 `20261003-refusal-anatomy-v7`，闻豆采用追加修订 `20261003-wendou-joint-v1`。源素材的视觉签收记录保留在人物工作交接中；安装与播放验证记录在 `build/validation/character-actions-v0.4.0/`。职业动作属于视觉与生活状态，尚未接入职业产出。

设置 → 动物与宠物中邀请动物、查看物种、品种、花色、体型、感官与行为，并绑定独立模型或选择气质预设。动物按 scale 显示相对大小，按饥渴、精力、时间与物种动作列表生活；警觉个体会避开近距离的居民刺激。真实动物 API 只可输出允许的动作、感官代码、需求代码，包含人类思想独白或对白的输出会被拒绝并回退本地行为。真实动物不参与居民对话，不显示人类语言气泡。原 Codex Mini 中的人形与幻想角色保持原人格，可像居民一样聊天、选择人设与绑定 API；其原始动画逐帧时长会被保留。旧存档启动时补全新增目录角色，保持已编辑居民、记忆与模型配置。

工作、游玩、相遇、休息区域是可隐藏的白板标记。尚无地形、建筑、障碍寻路、实体碰撞、职业产出、农场、货币、交易和任务。“晴”为静态界面文案，不代表天气系统。

精力与社交满足采用数值规则；个人心情结合真实经历、性格差异和模型在同一次回复中的自评变化；模型负责人物的目标、心声、台词、可用动作选择及交流中的独立感受，不构成真实心理模拟。事件记忆保留最近 16 条；私聊成功后通常保留最近 120 条，每次携带最近 24 条非错误消息。独立每日日志保留实际记录，基础上下文携带近期片段，尚无长期语义检索和事实校验。

## 开发验证

```sh
npm test
npm run test:renderer
npm run test:player
npm run test:batch
npm run test:api
npm run test:time
npm run test:life
npm run test:mood
npm run build:mac
```

后端测试覆盖居民、动物、主角、素材与存档，以及基础资料、个人目标、自主调度、多轮分歧、独立感受、近期上下文与长期日志。test:renderer / player / batch 覆盖动画、主角和批量设置；test:time 覆盖昼夜与知秋素材修复；test:api 覆盖心声、台词和动作。test:life 使用本地 HTTP/SSE 模拟服务与隔离存档，验证不手动触发行为的行走、主动邀约、三轮分歧、目标延续、日志筛选导出、资料编辑、1040×720 布局与重启恢复。test:mood 使用同类隔离服务，验证自动打盹、到达后恢复、个人心情与日志、九轮对话自愿结束、45 个形象的 135 个休息姿势、小窗口和重启；单元测试另覆盖第七轮等待时暂停取消。上述测试均不调用用户 API。实际服务商运行验证单独记录在本轮安装报告中。架构与扩展建议见 [HANDOVER.md](HANDOVER.md)。

# 像素小镇开发交接

本交接依据 v0.8.1 当前源码，并保留此前各轮验收记录。目标是在原 AI Chat 内核基础上独立开发俯视 2D 生活游戏；当前包含居民操控、持续模型生活、昼夜和独立每日日志，尚非完整星露谷类游戏。

## 产品约束

- 原 AI Chat 与新应用并存，只在 `pixel-town-app/` 中迭代，使用新数据路径；原配置与人设仅由用户点选后只读复制。
- 主界面是游戏：白板场景、角落 HUD、底部控制、临时人物互动条。聊天使用弹窗，人物和 API 参数全部在设置中。
- 初期地图留白。原 20 人的 16 张 PNG 保留；另有 20 人、20 只自然动物与 5 位 Codexmini，每个目录自带动作清单与档案。人物男女各 20 人；新增一批男女各 10 人，脸型与五官分别设计。
- 自由选择人数，每人形象、人设、API 绑定独立。可键盘操控、释放控制后自主生活、走向相遇区再交流。
- 地图、建筑、农场、经济、任务尚未实现，介绍与后续验收都应保持这条边界。

`main/llm.js` 是新项目自己的副本，修改不会自动写回原文件。与原内核有局部差异：Anthropic 重试分支使用 `proxyAwareFetch`，不要声称两份逐字相同。

主进程每 100 ms 调用 `tick(0.1)`，每两次 Tick 推送一次快照。场景逻辑坐标为 1600 × 1000，移动限制在边界内。目前直线移动，没有地图网格寻路或碰撞。界面用 `requestAnimationFrame` 切换素材帧，按人物纵坐标安排层级。

## 人物与生活数据流

居民包含 `persona`、`model`、`profileMd`、`memory`、`messages`、`relationships`、需求数值、位置、动作、目标和相遇状态。默认目录 45 位，最多同时设置 60 位居民，超出可用目录时复用形象但新建独立实例。停用不会删除历史。动物单独存入 `pets`，按物种设定体型、速度、感官和允许行为。

人物与 Codexmini 各有 3 套可选背景，动物各 2 套气质；旧存档补充新增目录，同时保留已有实例的名字、自定义人设、模型和记忆。真实动物只可返回 `action`、`senses`、`need` 三个字段，不参加人类对白与关系系统。Codexmini 的人形/幻想身份可像居民一样交流，不能把其行为套给真实动物。

`town:control` / `town:input` 管理一个受控人物，WASD / 方向键由界面提交；失焦、弹窗和设置会释放按键。设置打开暂停，返回恢复此前运行状态。`town:invite` → `meet()` 安排双方走向相遇区，到达后 `converse()` 发起并由双方意愿持续交流，更新双方记忆、关系与需求；当前为双人交流。

`localAction()` 根据需求、时间与性格关键词安排活动。模型决策只接受动作白名单 JSON，不能直接写文件、修改世界规则。`prompt()` 注入人设、Markdown 档案、16 条最近事件摘要、需求、时间和邻居状态。私聊成功后通常保留 120 条，单次携带最近 24 条非错误消息；没有检索、摘要压缩、长期事实图谱。

模型自治关闭时自动对话使用本地模板，手动交流仍按双方绑定模型分别调用。`locked()` 串行化生活任务；`request()` 开始即登记统计，失败也计数。`apiInterval` 约束自动任务，手动请求可立即发起。自主交流不设固定轮数上限，任何一人不愿继续即结束，已生成的邀请开场白复用；每次继续前检查剩余每日额度。模型内核的参数回退 / 503 重试可能增加 HTTP 尝试，次数统计不是费用硬上限。服务商测试不计入生活统计。

## 数据边界与恢复

正式：`~/Library/Application Support/pixel-town-life/`；开发：`~/Library/Application Support/pixel-town-life-dev/`；测试：通过 `PIXEL_TOWN_DATA_DIR` 指向隔离目录。均不使用原 `ai-friends-chat` 存档。

原配置入口读取 `~/Library/Application Support/ai-friends-chat/settings.json`，原人设入口读取同目录 `friends.json`。服务商复制为 `legacy-` ID，同 ID 已存在则跳过，不持续同步。人设先填入表单，再保存；私聊不迁移，开发目录不自动导入。

密钥只由主进程持有，实时快照脱敏。safeStorage 加密不可用时拒绝保存密钥，不以明文落盘；服务商保存成功须已同步存档成功。加密值依赖本机系统环境，跨电脑复制不保证可解密。导出 JSON 不含密钥，目前无界面导入功能。

存档写 `.tmp`，保留上一份 `.bak` 后替换主文件。损坏时尝试备份恢复并保留损坏副本；仅有一份滚动备份，不提供长期版本回退。两份都损坏或密钥无法解密时恢复可能失败。更改 schema 前应另存副本，增加显式迁移和恢复验证。

## 动作和玩法边界

40 位人物每位有 14 组连续动作：原 11 组另加点头、摇头拒绝、交谈手势。原动作每组 16 帧、80 ms/帧；点头/交谈每组 16 帧、90 ms/帧，摇头每组 25 帧，前 24 帧各 30 ms，末帧 480 ms。自然动物共 310 组，Codexmini 共 50 组，合计 920 组动作。01～20 号 frame_11/12 已替换为用户确认的背走两步，欢呼使用独立图集，基础帧与图集来源按 animation.json 区分。

游戏按 `animation.json` 使用 PNG 图集，GIF 是独立预览；暂停会冻结帧时间，速度倍率同步作用于播放，当前只加载在用动作。Codexmini 保留实际不等时长原帧，缺少上下行走、进食或睡眠等动作时明确回退。人体与动物程序骨骼补帧仍是近似，精细接触、遮挡、兔子跳步及完整清洁动作未达到逐帧手修级别。原人物部分白衣/鞋/帽透明缺色是源图问题，未覆盖原件。

目前无地图瓦片、建筑室内外、作物、背包、货币、交易、任务、天气、职业产出和避障。区域为可隐藏白板标记，情绪与关系为简单规则，不能作为真实心理模拟证明。

## 启动与验证

用 `npm start` 启动，脚本优先解析本项目 Electron、然后上级现有依赖。独立搬走后用 `npm install`、`npm start`。构建脚本优先使用上级 Electron / undici，回退本项目依赖；已有新应用构建会另名保留，再生成 `dist-mac/像素小镇.app`。

```sh
npm test
npm run test:renderer
npm run build:mac
```

接手时在隔离数据目录验证居民人数、键盘与鼠标、暂停恢复、释放操控、相遇双方回复、分别绑定模型、调用失败与上限、明确开启自治后的重启恢复、旧档默认关闭、密钥脱敏、损坏恢复。真实服务商验证会访问网络并可能收费。

构建后另查 `.app` 启动、正式路径隔离、素材加载、存档重启和原应用并存。本机临时签名不能替代正式分发签名与公证。避免用用户正式存档做破坏性验证。

## 扩展接口建议（未实现）

1. `WorldMap`：把区域坐标抽为图层、可行走区域、交互点和建筑入口数据，保留默认白板模式，再加入地图。
2. `MovementService`：沿用当前输入与移动 IPC，在引擎内部处理碰撞 / 寻路；模型提交目的地建议，由规则验证执行。
3. 动作转场与精修：沿用已有 animation.json 能力清单，增加站到坐等过渡、精细关节/工具接触、物种步态，修复旧源图的透明缺色。新增版本保留原件。
4. `Activity`：统一准备、移动、到达、执行、完成、取消；工作产出由引擎事件进入独立背包 / 经济模块，不让模型直接改余额或物品。
5. 世界事件与任务：事件带人物、地点、时间、结果，规则验证后更新任务和关系；模型提供表达与建议，规则状态作为事实源。
6. `MemoryStore`：区分实际事件、关系事实、人设与模型推断，设置检索、容量、摘要和撤销，不把想法自动当已发生事件。
7. 调度预算层：分别限制自动、手动、测试调用，加入 HTTP 重试统计和服务商金额预算；保留调用上限、暂停与取消机制，以及用户明确选择的自治恢复状态。

建议按地图与移动 → 动作与职业 → 物品与经济 → 任务与长期记忆迭代，每步保持游戏主界面和独立数据边界。

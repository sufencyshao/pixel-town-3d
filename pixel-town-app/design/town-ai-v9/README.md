## 打开与使用

1. 双击项目根目录的 `打开三维AI小镇.command`。这是本地 Electron 开发入口，不覆盖 `/Applications/像素小镇.app`。
2. 首次从原小镇 `~/Library/Application Support/pixel-town-life/` 复制存档和日志到 **`~/Library/Application Support/pixel-town-life-3d-v9/`**。之后独立保存；再次启动不会覆盖 V9。加密密钥仍由主进程 safeStorage 解密，页面拿不到密钥。
3. 选择人物，点击“查看发送给 AI 的资料”核对真实上下文，不发生模型调用。
4. 在“当前人物的模型绑定”中确认服务商、模型、温度和输出预算。需要新增服务商或修改人设，点击“API 与人物设置”，沿用原设置页面；返回后“刷新配置”。原居民的模型绑定可直接继承。未绑定真实 API 时不会假造 AI 返回。
5. 输入安排并点击“AI 决定下一步”，或留空让人物决定。示例：“先向邻居挥手，然后去工作点按职业流程练习，结束后休息。”
6. “当前人物自主行动”需手动开启，只为当前人物串行请求。切换人物、切后台、失败或“停止 AI 与当前行为”后关闭。调用间隔受原全镇最短间隔限制，调用总数受全镇每日上限限制；三维窗口打开时旧二维自动调度暂停，专用 V9 启动模式还会关闭复制来的旧自主开关。

直接打开 `三维小镇-AI生活.html` 是可离线的模型/环境/资料预览，浏览器页面没有 API 密钥访问和付费调用能力。**真正 API 操作请使用桌面入口。**

## AI 每次获得的资料

- 项目背景、价值取向、九区用途、米制坐标和实际能力边界。
- 45 位人物的当前公开身份、人设、背景、兴趣、表达风格、职业、作息；16 个在场动物/观景动物及 6 个未有合适模型的动物状态。
- 本人当前预设、生活方向、精力、情绪、私人记忆、存档中的单向好感，以及本人近期旧小镇日志。不会把其他人物的私人记忆或心声放进公开档案。
- 当前三维位置、时间、季节、天气、附近人物及距离/忙闲状态。
- 当前模型真实可用的原动作、语义关节到真实骨名的映射、逐轴角度限制、合法步态与当前职业任务。
- 最近实际执行回执、失败/中断原因、职业练习记录、其他人物确实送达的台词。未知人际关系不编造，同职业不等于好友；不会替别人回答或自动改好感。

稳定的世界与公开档案放在上下文前部；本人动态资料放在后部。不导入全部旧聊天，不发送全部可选人设，也不把旧二维坐标当作三维位置。

三维身份固定绑定原居民实例 ID。修改二维外观后仍沿用同一人的姓名、人格、API 和关系；三维模型继续保持作者成品。

## 可执行协议

模型只返回一个 JSON 对象，不执行模型输出的代码：

```json
{
  "version": 1,
  "thought": "先和大家打个招呼，再回到今天的练习。",
  "speech": "早上好，我先去整理一下工作安排。",
  "commands": [
    { "type": "preset", "clip": "Wave", "seconds": 2 },
    { "type": "pose", "joints": { "head": [0, 12, 0] }, "seconds": 2 },
    { "type": "work", "jobId": "daily:03_barista_male" }
  ]
}
```

这是林屿的示例。任务 ID 和动作必须来自当前人物清单，不能用于其他人物。每次最多 4 条，顺序执行：

| 指令 | 作用与执行条件 |
| --- | --- |
| `preset` | 播放当前模型已有动作，1–15 秒。44 成人有同库 10 项配套动作；儿童没有借用成人动作。走跑须配合 `move`。 |
| `pose` | 1–6 个关节的局部 XYZ 欧拉角增量，单位度，1–10 秒，叠加原动画后淡出恢复。只接受当前模型已开放的关节。 |
| `move` | `{destination:{x,z},gait:"walk"或"run"}`。有原步态才能移动；公共步道 0.5m 网格、最大高差 0.13m，检查静态可通行网格和其他角色占位；阻挡/不可达会停止并反馈。 |
| `work` | 前往本人已布置的公共室外工作点，按 3 个职业阶段计时执行并记录。使用真实原动作和小幅手臂姿态表现练习。当前预设可改变阶段说明。 |
| `social` | 对 4m 内空闲人物说话，需要 `speech`。对方的下一次独立决策才决定回应；已完成说话才写送达记录。 |
| `wait` | 原地等待/休息，1–60 秒，真实计时后完成。 |

当前开放头、颈、胸、左右上臂/前臂/手共 9 个语义关节。`capabilities.json` 记载真实 `Bip01_*` 名称与限制。禁止骨骼位移、缩放、根骨/腿/面部任意扭转。连续多条 `pose` 可以形成简单姿态顺序，不能声称已经实现抓取、足底约束或 IK。

## 工作的实际含义

40 位职业居民各有职业任务；5 位陪伴访客没有强派职业，儿童没有成人工作。前 20 位沿用原档案的 `occupationalBehaviors`；后 20 位补充明确的职业练习流程。工作点沿用 V8 的公共室外落位，属于运行练习位置，不代表人物已进入建筑操作内部设备。

只有到达、逐阶段计时完成、引擎回执通过验证并原子保存后，才增加 `workLog`。回执同时更新三维独立的精力/社交满足/完成练习后的心情值。动作计划、工作开始、取消和实际完成分别记录；失败的动作不会被写成成品。

**本版没有实物制作、工具握持/设备控制、货币交易、物品库存、室内与楼层导航、车辆驾驶、全身 IK、全动作接触或衣物物理。** 工作完成是一次职业练习完成，不能说已经烤出面包、给人完成治疗或交付产品。没有步态的猫犬马和鸟类保持原位，仅使用自身原动作/姿势；兔子已有原动作可以播放，但未开放动物自主位移与食水互动。缺失的 6 个动物继续保留档案。

## 实现与检查

- `main/town-3d-context.js`：真实档案/关系/能力上下文。
- `main/town-3d-service.js`：真实 LLM 接入、预算、过期结果丢弃、取消、绑定、回执与原子保存。
- `main/town-3d-preload.js` / `town-3d-window.js`：限定窗口 IPC；API 密钥留在主进程。
- `shared/town-3d-protocol.js`：主进程和三维渲染器共用严格协议。
- `src/ai-executor.js` / `navigation.js`：实际动作、骨架叠加/恢复、地面移动、职业阶段。
- `src/ai-panel.js`：上下文预览、配置、一次/自动请求、停止和失败后重试保存。
- `town-3d-life.json`：V9 数据目录下的三维历史、身份映射、位置、练习记录和收到的台词，不保存 API Key。写入失败时不更新内存，也不继续付费请求；窗口关闭/重载写中断记录，没有最终回执的不认定完成。

构建：在 `pixel-town-app/` 执行 `npm run build:3d`。原件和模型来源/许可沿用 `../whole-town-realistic-actors-v8/README.md`、作者原文件及许可证；本目录不重复改造原模型，也不重新导出静态 Blender 快照。

验证：`npm test`；`npm run test:3d`；`scripts/town-3d-main-smoke.cjs` 使用真实主程序进行隔离启动。完整证据见 `验收记录.md` 和 `qa/`。模拟服务商经生产 `llm.js` 的 HTTP/SSE 链路调用，真实第三方付费 API 未代为调用。

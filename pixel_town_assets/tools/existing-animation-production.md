# 原有 20 位人物：连续动作制作与验证

范围：`characters/01_hero_male` 至 `characters/20_student_female`。原始 `frame_01.png` 至 `frame_16.png` 均作为只读输入，动画写入独立 `animations/`。

每人现在有 11 个连续动作：`idle`、`walk_down`、`walk_left`、`walk_right`、`walk_up`、`wave`、`surprise`、`sit`、`jump`、`cheer`、`work`。每动作 16 帧、每帧 80 ms、循环时长 1.28 s，游戏用横向 RGBA 图集为 4096 × 256，每帧 256 × 256。每角色的 `overview.gif` 是 11 种动作按顺序展示的总览；动作之间是展示切换，不代表姿态过渡动画。

## 动作处理

- 从单个原始关键姿态出发，按头、肩、左右臂、髋、左右腿的空间权重进行独立旋转与位移；躯干有低幅度呼吸，不使用全图循环晃动或交叉淡入替代步行动作。
- 四方向步行包含左右肢体反相摆动、脚尖椭圆抬步轨迹、头部错相轻倾和两次重心下降。背面动作由原始 `frame_10` 的分区生成，修复旧素材缺背面步行循环的问题。
- 挥手、惊讶、坐下和欢呼采用各自原始关键姿态，避免在连续循环中切换不同生成图导致脸和服装跳变。
- 跳跃采用连续起跳、腾空、落地轨迹，预留顶部空间。坐姿保持坐姿呼吸，未把站立全图缩放冒充坐姿。
- 工作动作有独立手臂活动及对应职业的小型硬边工具：文书/书本、咖啡杯、面团/裱花袋、木工锤、邮封、急救包、浇水壶、吉他、锅铲、花束、画板调色盘、宠物食盆等。
- 最近邻采样保留硬边；Alpha 只包含 0 和 255。GIF 使用保留的透明调色板索引，PNG 保留原像素色彩。只清理派生帧中原始切片顶部小于 300 像素的孤立串片杂点，不改源图。
- 统一脚点在画布 y≈230，manifest 的 anchor 为 `[0.5, 0.9]`。角色静态高度 210 px，坐姿 168 px，跳起最多 15 px；变形不会碰到画布边缘。

## 文件与游戏接入

每个角色：

```
animation-manifest.json
 overview.gif
 animations/
   idle.png + idle.gif
   walk_down.png + walk_down.gif
   ...
   work.png + work.gif
   motion-preview.png
```

图集单行从左至右排列。在运行时按 `floor(elapsedMs / frameMs) % frames` 截取对应的 256 × 256 单元。GIF 用作预览，游戏加载 PNG 图集以统一控制时钟、动作和移动速度。每个解码图集约 4 MiB，应随使用加载，避免一次解码全部人物所有图集。

manifest 包含各动作的源图片和 SHA-256。`gifFrames` 用于核对 GIF 实际帧数，`frames` 是游戏图集帧数。

## 验证结果

`existing-animation-validation.json`：20 人、220 个动作、3520 个帧单元，错误列表为空。逐动作检查包括：RGBA 图集尺寸、二值透明通道、GIF 透明背景、16 帧数量、80 ms 总时长、无限循环、至少 12 个独立姿态、首尾连接差不超过其余相邻帧最大变化的 1.2 倍、画布无裁切。最终所有 220 动作均通过。

`existing-cast-motion.gif` 是 20 人同屏步行预览，单人 `animations/motion-preview.png` 可逐相位对比步行、挥手及工作时的独立身体运动。

复现：

```
python3 pixel_town_assets/tools/animate_existing.py
python3 pixel_town_assets/tools/verify_existing_animations.py
```

需要 Pillow 和 numpy；本项目可用 Codex 自带 Python。渲染脚本也支持 `--folders 角色文件夹名 ...` 选择已有其他角色目录。缺少动作专用关键姿态时会回退 `frame_01`，因此新增角色应先提供真实的 `frame_11/14/15/16`，尤其不能用站姿别名代替坐姿。

## 已知局限

这是对原有栅格素材的程序化骨骼分区连续化，并非每个职业手绘的逐帧高精度动画。衣服分区边缘可能出现细小形变；小比例显示有像素阶梯，符合硬边图集的采样方式。原图中部分白色衣物/白鞋被旧背景清理算法抠除，仍会透出场景底色；在本批任务中没有擅自重绘补色。原始姿态之间的脸型、头身比例和衣物差异仍存在，动画循环内部保持单一源姿态，切动作仍可能看到差异。

部分源 `frame_04` 只是左前侧视角，沿用其已有朝向。原始 `frame_14` 中部分人物举两手，故其挥手循环是双手招呼；`frame_11` 中部分角色是抬臂而不是举臂，故欢呼幅度保留原图。工作工具是通用职业表达，未模拟握持遮挡、精确碰撞或完整职业操作。站立到坐下、惊讶到恢复等跨动作转场需要游戏状态机另行处理，不能将 `overview.gif` 的动作切换当作连续转场。
